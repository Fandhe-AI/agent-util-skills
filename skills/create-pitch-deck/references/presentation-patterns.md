# 没入型プレゼンテーションの実装パターン集

PO 提示の参考サイト（自己完結 HTML・フルスクリーン・キーボード操作型プレゼンテーション）を
Playwright で取得し、CSS/JS を精読して演出メカニズムを一般化したもの。**参考サイト自体の
HTML・文言・具体的な題材（デモの内容・コピー）は一切含めない**。ここに記すのは「仕組み」の
言語化のみであり、`build_slides.py` の実装はこのパターン集を踏まえつつ、後述の
「本スキルでの採否」に従って PO の明示要件（フラグメントは自動再生でなく手動送り等）を優先する。

## 1. 全体骨格

```
.deck（position:fixed; inset:0; flex-column）
  .hud（常設。左: 区分ラベル、中央: 操作ヒント、右: n / N）
  .stagearea（flex:1; position:relative）
    .slide × N（position:absolute; inset:0; 非表示は opacity:0 + visibility:hidden）
      .slide.act（表示中: opacity:1 + transform:none）
  .progress（常設。スライド数分の <button> を横並び。クリックで該当スライドへジャンプ可能）
  .nextcue（画面下中央に浮く「次へ」ヒント。点滅アニメーション）
  .navbtns（画面右下に浮く前後ボタン）
```

- 非表示スライドは `opacity:0; visibility:hidden; transform:translateX(46px)` とし、表示時に
  `opacity:1; visibility:visible; transform:none` へ遷移させる。`transition-delay` を
  `visibility` にだけ掛けて「フェードアウトし切ってから visibility:hidden にする」ことで
  暗転時のちらつきを防ぐ。
- **プログレスバーは装飾ではなく実際にクリック可能な `<button>` 要素**にし、該当スライドへ
  直接ジャンプできるようにする（アクセシビリティ的にも `aria-label` を振る）。

## 2. ナビゲーションモデル

参考サイトは「スライドに入ると自走するタイムライン（`async` 関数が `await sleep(ms)` を
挟みながら演出を自動再生し、キー操作は基本的にスライド単位の前後移動のみ）」という設計
だった。これは**プレゼンター次第で間が伸び縮みする対話的な発表**には向くが、**機械検証
（本スキルの必須要件）で決定的に状態を再現するのが難しい**（wall-clock 依存）。

### 本スキルでの採否

PO の明示要件（スライド内フラグメントを `→` で手動送り）を優先し、**タイマー自動再生では
なく、キー入力で1ステップずつ確定的に進める方式**を採用する。参考サイトから輸入するのは
「状態遷移の視覚言語」（次項以降）であり、「時間経過で自動再生する」という駆動方式そのもの
ではない。

それでも参考サイトから汎用化して踏襲する操作系:

- `→` / `Space` / `PageDown`: 次へ（スライド内フラグメントが残っていればフラグメント優先、
  尽きていれば次スライド）
- `←` / `PageUp`: 前へ（対称的に、フラグメント0の状態で戻ると**前スライドの最終フラグメント
  状態**へ戻る。単純に「前スライドの先頭」に戻ると逆再生として不自然になるため）
- `Home` / `End`: 先頭 / 末尾スライドへジャンプ
- `R`: 現在スライドのフラグメントを先頭へ巻き戻す（参考サイトの「タイムライン再生し直し」を
  「フラグメント状態リセット」に読み替えたもの）
- クリック: 画面端の前後ボタン、プログレスバーの各セグメント
- タッチスワイプ（左右）: スライド前後移動

## 3. フラグメント（ステップ送り）の状態表現

参考サイトはキャプションリストの各項目に3状態を持たせていた: 「未到達」（大きく減光）・
「現在」（強調＋先頭にマーカー記号）・「既読」（中間の減光）。

一般化した CSS 契約:

```css
.fragment { opacity: .16; transition: opacity .35s, transform .35s; }
.fragment.is-current { opacity: 1; }
.fragment.is-current::before { content: "▶"; /* 現在地マーカー */ }
.fragment.is-done { opacity: .5; }
```

JS 側は「現在ステップ番号 i」だけを状態として持ち、`setStep(slide, i)` が全フラグメントへ
`is-current`（index===i）/`is-done`（index<i）を re-render のたびに再計算して付け替える
（差分更新ではなく毎回全体を再計算する方が、逆再生・スライド切替時の考慮漏れを防げる）。

ステップ数はフラグメント要素数から**導出**する（spec に「何ステップか」を別途持たせない）。
`screen_flow` のみ、画面ハイライトの対象を指定する必要があるため `steps` を明示的に持つ
（後述）。

## 4. キーとなる一言（テイクアウェイ）の演出

参考サイトは各スライドの締めに、アクセントカラーの左ボーダー＋薄い背景色を敷いた「結論
ボックス」を用意し、そのスライドの最終フラグメントとして fade + 上方向スライドで出現させて
いた。要点を1つに絞って強調する効果がある。一般化:

```css
.takeaway {
  border-left: 3px solid var(--color-accent);
  background: color-mix(in srgb, var(--color-accent) 8%, transparent);
  opacity: 0; transform: translateY(8px); transition: .45s;
}
.takeaway.is-current, .takeaway.is-done { opacity: 1; transform: none; }
```

## 5. 「動く画面デモ」の一般化（screen_flow の核）

参考サイトは題材固有の凝った手描きモック（ゲーム風のキャラクター移動・業務画面のサイドバー
＋テーブル等）を JS で逐次アニメーションさせ、加えて**疑似マウスカーソル**を対象要素の位置
まで CSS transition で移動させ、クリック演出（要素側は押し込みスケール、カーソル側は
弾む scale）を同期させていた。空データ→テーブル出現のような状態遷移、フォームの入力済み
/エラー/合格チェックの出現、トースト通知のスライドインなど、**すべて「クラス付け替え＋
CSS transition」で実現**されており、JS 側は「いつどのクラスを付けるか」のタイミング表
（タイムライン）を持つだけだった。

本スキルでは題材ごとに手描きモックを作る代わりに、**`create-design-doc` が生成した実際の
`wireframes/*.html` を `<iframe srcdoc="...">` で実寸レンダリングし、`transform: scale()` で
枠内に収めて「本物の画面」を見せる**方式を採る（PO 指示）。カーソル移動の代わりに
**スポットライト**（対象要素だけ発光・全体をわずかに減光）で注目箇所を示す。

### 疑似マウスカーソル移動の考え方（参考サイトの一般化）

対象要素の位置を「コンテナ基準の相対座標」で求め、コンテナに `transform: scale()` が
掛かっている場合はその**実効スケール**で座標を割り戻してから疑似カーソル要素の
`left`/`top` に反映していた（`getBoundingClientRect()` は変換後の見た目サイズを返すため）。
本スキルではカーソル移動そのものは採用しないが、**スクロール位置・ハイライト位置の計算でも
同じ「表示後の座標を実効スケールで補正する」考え方**が必要になる（iframe 内の座標系は
iframe 自身の `contentWindow` を基準にすればスケールの影響を受けないため、実際には
iframe 内部の `scrollIntoView` + クラス付与で完結し、親側の座標計算は不要— 後述）。

### 実装方針（本スキル）

1. `screen_flow.wireframe` に `create-design-doc` の `wireframes/*.html` への相対/絶対パス
   を指定する
2. `build_slides.py` がそのファイルを読み込み、**自己完結性チェック（外部 URL・危険な JS
   パターンの不在）を生 HTML の時点で実施**してから `srcdoc` 属性値として HTML エスケープ
   し埋め込む（エスケープ後は正規表現での外部参照検出が効かなくなるため、チェックは
   埋め込み前の生テキストに対して行う）
3. `steps: [{selector, note}]` で、ステップごとに強調したい要素（CSS セレクタ）と、右側に
   出す説明文を指定する
4. 親ドキュメントの JS が、フラグメント送りのタイミングで `iframe.contentDocument` を
   直接操作する（`file://` 実行時・`srcdoc` いずれでも同一オリジン相当としてアクセス可能な
   ことを実機検証済み）:
   - 前ステップで付けた `.spotlight` クラスを対象要素から外す
   - `steps[i].selector` に一致する要素へ `.spotlight` を付与
   - `element.scrollIntoView({behavior:'smooth', block:'center'})` で見える位置へ寄せる
   - 右側の説明リスト（`.screen-flow-steps li`）側は通常のフラグメント機構（`is-current`/
     `is-done`）で連動させる
5. スポットライトの CSS はオーバーレイ全体を薄く減光しつつ対象だけ `outline` + `box-shadow`
   の発光を与える方式にする（対象要素の `position` を変えない。`outline` はレイアウトに
   影響しないため安全）

### iframe の scale とレイアウト崩れの罠（実測で確認）

`transform: scale()` は**レイアウト上の占有サイズを縮小しない**。iframe に直接
`transform:scale(0.42)` を掛けても、周囲の要素からは元のサイズ（例: 1440px 幅）のまま
扱われ、`.slide` 自身の `scrollWidth` がビューポートを超えてしまう（実測: ラッパー無しで
幅 1440px の iframe を 0.42 倍表示すると `.slide.scrollWidth` が 1480px まで膨張した）。
**スケール後の実寸に固定サイズ＆`overflow:hidden` のラッパー**で iframe を包み、iframe 自体
は `position:absolute; top:0; left:0; transform-origin: top left` にすることで解決する
（同条件で実測 `scrollWidth` が 1440px に収まることを確認済み）。

## 6. マイクロフィードバック（"juice"）

参考サイトは「達成の瞬間」を強めるために、パーティクル状の小片が中心点から放射状に飛び散る
演出と、短いテキスト（達成量など）が浮き上がって消える演出を持っていた。両方とも
「JS で要素を動的生成 → CSS keyframes で移動・消失 → `setTimeout` で自身を DOM から除去」
という共通構造。本スキルでは「勝ち筋」スライドの数値カウントアップ完了時など、**節度を保って
局所的に**使う（多用すると業務プレゼンとして品位を損なう。PO も「過剰にしない」と明記）。

## 7. アクセシビリティ・堅牢性まわり

- `@media (prefers-reduced-motion: reduce)` で全アニメーション・トランジションの継続時間を
  実質ゼロにする分岐を用意していた（本スキルでも踏襲する）
- 印刷時（`@media print`）は「今どのステップか」を無視し、**全フラグメントを最終状態
  （表示済み）にする**必要がある。クラスによる状態管理と CSS の優先順位次第で「1枚だけ見せ
  たいのに前のステップが消えたまま印刷される」事故が起きやすいため、print 用のルールで
  `opacity/transform` を明示的に上書きする
- 各スライドに**発表者用メモ**を `<template class="note">...</template>` として埋め込む
  手法があった。`<template>` の中身は既定で描画されないため、聴衆向け表示に影響を与えずに
  自己完結 HTML 内へ発表メモを同梱できる（本スキルでも任意項目として採用可）

## 8. 本スキルへの取り込み一覧（要約）

| 参考サイトの仕組み | 本スキルでの扱い |
|---|---|
| スライド遷移（フェード＋スライドイン、visibility 遅延） | 採用（既存実装を踏襲・強化） |
| プログレスバーがクリック可能なボタン | 採用 |
| キャプションの on/done/dim 3状態 | 採用。ただしフラグメント（`.fragment`）という汎用名で全 role の箇条書きに適用 |
| テイクアウェイ（結論）ボックスの強調演出 | 採用（`winning`/`approval` 等の最終フラグメントに使える汎用パターンとして提供） |
| 自動再生タイムライン（`await sleep`） | **不採用**。PO 指示によりキー入力駆動の手動フラグメント送りに置き換える |
| 疑似マウスカーソル移動＋クリック演出 | **不採用**（手描きモックを前提とするため）。代わりに実ワイヤーフレームへのスポットライト＋スムーズスクロールを採用 |
| 空データ→テーブル等の状態遷移 | 実ワイヤーフレーム側（create-design-doc）の責務。本スキルは「どこを見るか」の誘導のみ担当 |
| パーティクル/ポップテキストの juice | 数値カウントアップ演出に限定して採用 |
| prefers-reduced-motion 対応 | 採用 |
| print 時に全ステップ表示 | 採用（PO 明記） |
| 発表者メモの `<template>` 埋め込み | 任意項目として仕様に記載（spec に notes を持たせる場合のみ） |
| 小画面での deck 全体スケール対応 | 対象外（本スキルは 1440×900 のプレゼン用途に限定し、レスポンシブ対応は将来課題とする） |
