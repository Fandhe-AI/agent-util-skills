# concept-brief.md スキーマ

`create-pitch-deck` と `create-design-doc` が共有する合意文書 `concept-brief.md` の構成。
**両スキルで内容が食い違わないための共通の中間成果物**であり、本ファイルは両スキルの
`references/` に同一内容で置く（各スキルが単独導入されても自己完結して読めるようにするため。
`.claude/rules/skill-authoring.md` の導入先非依存性に従う）。

## 位置づけ

- 先に実行されたスキルが入力文書から起案し、ユーザー確認を経て確定する。
- 後から実行されたスキルは、この文書を**必須入力**として読み、矛盾する成果物を作らない。
- 置き場所は各スキルの成果物ディレクトリと同階層が既定。**2 スキルを連携させる場合は
  `--brief <path>` で同一パスを明示指定する**（既定値はスキルごとに異なるディレクトリ配下の
  ため、指定なしでは自動的に共有されない）。

## 必須セクション

各項目には**出典**（入力文書のどの部分から解釈したかの根拠。文書に根拠が無く推測で補った
場合は「推測」と明記）を付記する。

| # | セクション | 内容 |
|---|-----------|------|
| 1 | 課題定義 | 誰の・どんな痛みを解くか。なぜ今か |
| 2 | ターゲットユーザー | 主要な利用者像（属性・利用文脈） |
| 3 | 解決コンセプト（1文） | プロダクトが提供する価値を1文で |
| 4 | スコープ In・Out | 対応する範囲・対応しない範囲 |
| 5 | プロダクトのトーン＆マナー | デザイン方向性の言語化（例: 「業務効率化ツールらしい機能的な信頼感」「個人クリエイター向けの親しみやすさ」） |
| 6 | 主要ユーザーシナリオ | 2〜3個。いつ・どこで・何のために使うか |

## テンプレート

```markdown
# concept-brief.md

## 1. 課題定義
- {課題}
- 出典: {入力文書名・節、または「推測」}

## 2. ターゲットユーザー
- {ユーザー像}
- 出典: {...}

## 3. 解決コンセプト（1文）
- {1文}
- 出典: {...}

## 4. スコープ In・Out
### In
- {...}
### Out
- {...}
- 出典: {...}

## 5. プロダクトのトーン＆マナー
- {トーン記述}
- 出典: {...}

## 6. 主要ユーザーシナリオ
1. {シナリオ1: いつ・どこで・何のために}
2. {シナリオ2}
- 出典: {...}
```

## 相互整合チェックでの使い方

後から実行されたスキルは、最終ステップで自分の成果物を本ファイルと照合する。

- 課題定義・スコープ・トーンに矛盾がないか
- （もう一方の成果物が発見できる場合）用語・呼称の不一致、課題と解決内容の対応漏れ、
  スコープ外機能の混入がないか

矛盾を検出した場合は**どちらも上書きせず**、「concept-brief.md を直すか／成果物を直すか」を
ユーザーに提示する。
